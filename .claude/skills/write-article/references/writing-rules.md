# 記事の文体ルール（2026-11-20 ユーザーのフィードバックから）

## 改行

- **1文ごとに改行する。** 句点（。）のあとは必ず `<br />`。段落（`<p>`）は意味のまとまりで分ける。1段落は2〜4文
- 句点が続いているのに改行がない文章は読みづらい、というのが本人の指摘。例外は箇条書きの中と表のセル

## 文章体にする

台本は話し言葉で書かれている。記事では文章体に直す。

| 話し言葉（台本） | 記事 |
|---|---|
| 僕は、〜なんです、〜なんですよね | 私は、〜です |
| 正直に言うと、ノリと感覚で | 根拠を積み上げずに感覚で |
| ちょっとした、だいたい、まあ | 小さな、およそ、（削る） |
| 〜してみてください、〜でいいんです | 〜してください、〜で足ります |
| これは次の話です | これは次の節で扱います |
| 同じことを言い換えて2回言う | 1回にする |

- 1文は短く。読点で2つ以上の内容をつながない
- 冗長さは削る。動画で間を持たせるための言い直し・念押しは記事に要らない
- 「責める話ではありません」のような相手を安心させる一言は残してよい（誠実トーン）。ただし1節に1回まで

## トーンと言葉（DESIGN_CONSTRAINTS 5 と同じ）

- 結論を最初に1行で言い切る。見出しの直後も結論から
- 社長が読める言葉。IT用語は使わない。使うなら直後に一言で言い換える
- 煽らない。恐怖訴求しない。開発会社を悪者にしない（「売る側も整理していなかった」の視点）
- 数字は動画と同じものだけ。サンプルはサンプルと明記
- 一人称は「私」。動画では「僕」だが記事では「私」

## 構成（固定）

1. kicker（シリーズ名 — テーマ）
2. h1（検索語を含む。「社長が」「確かめる方法」のように、誰が何をするかが分かる形）
3. meta（公開日 ｜ 著者と立場 ｜ 動画の尺）
4. lead（結論1文、太字の帯）
5. 動画の埋め込みと「記事の内容は動画と同じです。」
6. 本文。h2は `01`〜 の番号つき。まとめをh2の最後に置く
7. 明日やること（行動1つ。文面があれば引用枠）
8. 次の一歩（有料1つ、無料相談1つ）
9. 注記（関連記事、サンプルである旨）

## タイトルとdescription

- title: 記事名 + ` | 打田裕馬 — フラクショナルCTO`。記事名は40字以内
- description: 120字前後。結論と、誰向けかと、著者の立場（元開発会社社長）を入れる
- og:image は動画のサムネ（`https://i.ytimg.com/vi/<id>/maxresdefault.jpg`）
