社長のためのシステム開発 — 発注の進め方

頼んだものと違うシステムができる理由と、社長が防ぐ2つの方法

2026年11月11日公開 ｜ 打田裕馬（元システム開発会社社長・フラクショナルCTO）｜ 動画 6分

社長と開発会社だけで決めないでください。原因の多くは、ふだんの業務をしているスタッフの意見が入っていないことです。

記事の内容は動画と同じです。

頼んだものと違うシステムができてしまう。
今でもよくあることです。
防ぐ方法は2つあります。
現場のスタッフを担当窓口にすることと、AIで見本を作って打ち合わせに持っていくことです。

01現場のスタッフを担当窓口にする

システムの中身は、ふだんその業務をしているスタッフに決めてもらってください。
小さな会社ほど、社長と開発会社だけでやり取りして決めがちです。
従業員が10人以下の会社でも、現場のスタッフを1人、担当窓口にしてください。
社長は決める人ではなく、後ろからフォローする役に回ります。

私自身、先月この失敗をしました。
たまにしか起きないので見逃しやすい例外の使い方が、仕様から抜けていました。
その結果、システムでエラーが起きました。

実際に使う担当者を打ち合わせに呼んでいれば、おそらく漏れませんでした。
忙しさを理由に、社長とのやり取りだけで決めてしまった私のミスです。
作る側でも、使う人の話を聞かなければ漏れます。

02AIで見本を作って、打ち合わせに持っていく

こうした漏れは、AIを使うとかなり事前に潰せます。
プログラミングの仕組みが分からなくても、見た目だけ動く見本を作れるからです。
この見本をプロトタイプと呼びます。

見本を社内で共有したり、開発会社に見せたりすると、足りないところが見つかります。
口頭や文章だけの打ち合わせより、話の精度が大きく上がります。

開発会社が見本を作ってくれる場合もあります。
私は時間が許す限り、話を伺ったうえで見本をA・B・Cの3パターン用意します。
どれがイメージに近いか、どれが使いやすそうかを選んでもらうためです。
ただ、すべての開発会社が見本を作ってくれるわけではありません。
自社で作って持っていけば、作り直しの少ない開発になります。

作るための道具は、Claude Code や ChatGPT の Codex などがあります。
どちらも、言葉で頼むとアプリを作ってくれるAIです。
システムを作ったことがなくても、AIを触ったことがなくても、一度試す価値はあります。

03見本があると、見積もりが下がることもある

開発費には、プログラムやサーバーの費用だけでなく、最初の打ち合わせにかかる人件費も含まれています。
発注する側が先に情報を出せば、その分の手間が減ります。
見積もりが下がることがありますし、見積もりの精度も上がります。

発注側が細かいところまで握りすぎるのはよくありません。
それでも、自分でAIを触って開発の流れを知っておく価値はあります。
見本や画面のデザインを作る時間が減れば、そのぶん見積もりも下がるはずです。

04開発の時間の使い方が変わった

以前のシステム開発は、何を作るか決める設計の工程と、プログラムを書く工程に分かれていました。
時間の多くを占めていたのは、プログラムを書く工程です。
今はこの工程を、AIで大きく短くできます。

そのぶん、何を作るかを決める工程に時間を使えるようになりました。
この工程を上流工程と呼びます。
社長にも、AIを使いながらこの上流工程に参加してほしいと考えています。

05全部自分で作ればいいのか

見本が作れるなら、全部自分で作ればいいと考える方もいるでしょう。
できなくはありませんが、おすすめしません。
最近は巧妙な攻撃が増えていて、守りの弱いところがあると情報が漏れる可能性が上がるからです。

何を作るかは、開発会社と相談しながら社長が決めてください。
プログラミング、サーバーの構築、セキュリティ対策は、専門家に任せてください。

06まとめ

  • 社長と開発会社だけで決めない。どんなに小さな会社でも、現場のスタッフを担当窓口にする
  • 社長は決める人ではなく、後ろからフォローする人
  • AIで見本を作って持っていくと、開発会社がイメージしやすくなり、開発費が下がることもある
